# OpenPeer — 项目需求文档

## 1. 系统概述

OpenPeer 是一个去中心化学术评价平台。作者可以自由发布论文，社区读者通过评分和评论对论文进行评价。论文的最终得分由所有读者的加权评分动态计算得出，取代传统同行评审机制。

### 1.1 核心价值

- **去中心化**: 无传统审稿人，由社区驱动质量评价
- **开放获取**: 论文公开发布，降低学术壁垒
- **透明评价**: 所有评分和评论公开可见
- **信誉驱动**: 高质量评价者通过信誉分获得更大权重

---

## 2. 用户角色

| 角色 | 权限概述 |
|------|----------|
| **游客 (Visitor)** | 浏览论文列表、搜索、查看详情、查看评分和评论 |
| **读者 (Reader)** | 注册后获得: 评分、评论、个人信息管理 |
| **作者 (Author)** | 继承读者权限 + 上传/管理论文 |
| **管理员 (Admin)** | 系统管理: 分类管理、内容审核、用户管理 |

> **说明**: Reader 和 Author 并非独立角色。任何注册用户都可以同时是 Reader (评分评论) 和 Author (发布论文)。`UserRole` 枚举主要用于权限判定标记，未来可扩展为 RBAC。

| F-03 | Token 刷新 | 使用 Refresh Token 获取新 Access Token | P0 |

## 4. 非功能需求

### 4.1 性能

| ID | 指标 | 阈值 |
|----|------|------|
| NF-01 | API 响应时间 (P95) | < 200ms |
| NF-02 | 并发用户支持 | ≥ 100 |
| NF-03 | 前端首屏加载 (FCP) | < 2s (4G 网络) |
| NF-04 | 前端页面切换 | < 300ms |
| NF-05 | 数据库查询 (单表) | < 50ms |

### 4.2 安全

| ID | 要求 | 说明 |
|----|------|------|
| NF-06 | 密码强度 | 最少 8 位，必须包含字母和数字 |
| NF-07 | JWT 安全 | HMAC-SHA256 签名, Secret ≥ 256bit |
| NF-08 | Token 过期 | Access Token 1h, Refresh Token 7d |
| NF-09 | 文件上传 | 仅接受 PDF MIME, 限制 10MB |
| NF-10 | API 限流 | 登录 5/min, 注册 3/min, 上传论文 10/min |
| NF-11 | CORS | 允许源白名单，不允许 `*` |
| NF-12 | HTTPS | 生产环境强制 TLS 1.2+ |
| NF-13 | 敏感数据 | 密码永不明文传输或存储 |

### 4.3 可用性

| ID | 要求 | 说明 |
|----|------|------|
| NF-14 | 响应式布局 | 桌面端 (≥1024px) + 平板端 (≥768px) |
| NF-15 | 加载状态 | 所有异步操作有 loading 指示 (骨架屏/Spinner) |
| NF-16 | 空状态 | 无数据时展示友好的空状态提示 |
| NF-17 | 错误提示 | 错误信息准确具体, 指导用户如何修正 |
| NF-18 | 表单校验 | 前端即时校验 + 后端兜底校验 |
| NF-19 | 确认操作 | 删除等不可逆操作有二次确认弹窗 |

### 4.4 可维护性

| ID | 要求 | 说明 |
|----|------|------|
| NF-20 | 后端测试覆盖率 | 核心服务层 > 70% |
| NF-21 | 前端测试覆盖率 | 关键组件和 Store > 60% |
| NF-22 | 结构化日志 | Serilog 输出 JSON 格式日志, 包含 TraceId |
| NF-23 | API 文档 | Swagger UI 完整覆盖所有端点 |
| NF-24 | 数据库迁移 | 所有 Schema 变更通过 EF Core Migration |
| NF-25 | 代码审查 | PR 必须至少一人审查通过 |

### 4.5 兼容性

| ID | 要求 | 说明 |
|----|------|------|
| NF-26 | 浏览器支持 | Chrome/Edge/Firefox/Safari 近两年版本 |
| NF-27 | 移动端适配 | 平板端布局可用, 手机端可降级 |

## 6. 用户故事

### US-01: 发现高质量论文

> 作为一名学术爱好者，我希望在首页按评分排行浏览论文，并能按学科分类筛选，以便快速找到我感兴趣领域的高质量研究成果。

**验收标准:**
- [ ] 首页默认按平均评分降序显示论文列表
- [ ] 每篇论文卡片显示: 标题、作者用户名、平均分星级、评论数、发布时间
- [ ] 顶部有分类标签可点击筛选
- [ ] 排序下拉可切换: 最新 / 最高评分 / 最多评论
- [ ] 有搜索框可按关键词检索
- [ ] 列表底部有分页控件

### US-02: 发布研究论文

> 作为一名研究者，我希望将自己的预印本上传到平台，填写必要的元数据，接收社区的反馈和评价。

**验收标准:**
- [ ] 登录后导航栏出现"上传"入口
- [ ] 上传页面包含: 标题输入框 (必填)、摘要文本框 (必填)、分类选择 (可选多选)、PDF 上传区
- [ ] 文件仅接受 PDF, 大小不超过 10MB, 否则提示错误
- [ ] 标题长度 5~200 字符, 超出时实时提示
- [ ] 摘要长度 20~2000 字符, 超出时实时提示
- [ ] 提交成功后跳转至新论文的详情页
- [ ] 提交失败时表单保留已填内容, 显示具体错误信息

### US-03: 评价论文

> 作为一名读者，我希望对感兴趣的论文打出我的评分并写下评论，以表达我对该研究的看法。

**验收标准:**
- [ ] 论文详情页展示可交互的 5 星评分组件
- [ ] 鼠标悬停时高亮星星, 点击提交评分
- [ ] 已评分状态显示当前分数, 再次点击进入修改模式
- [ ] 评分操作需要已登录, 未登录时提示先登录
- [ ] 评分分布区域显示各星级数量和平均分
- [ ] 评分提交后有 toast 提示成功

### US-04: 参与学术讨论

> 作为一名读者，我希望在论文下方发表评论并回复他人的评论，与社区进行学术交流。

**验收标准:**
- [ ] 论文详情页底部有评论区
- [ ] 评论列表按发表时间正序排列
- [ ] 每条评论显示: 用户头像/用户名、发表时间、内容
- [ ] 每条评论有"回复"按钮, 点击后展开回复表单
- [ ] 回复嵌套在父评论下方, 缩进显示
- [ ] 发表评论/回复后即时出现在列表中
- [ ] 自己发表的评论有"编辑"和"删除"按钮
- [ ] 删除操作弹出确认对话框

### US-05: 管理我的内容

> 作为一名平台用户，我希望在个人中心统一查看和管理我上传的论文、打出的评分和发表的评论。

**验收标准:**
- [ ] 个人中心分标签页: 我的论文 / 我的评分 / 我的评论
- [ ] "我的论文"列出我上传的所有论文, 每篇有编辑和删除按钮
- [ ] "我的评分"列出我评分过的所有论文及分数
- [ ] "我的评论"列出我发表的所有评论
- [ ] 可编辑个人简介

## 7. 数据约束

| 字段 | 约束 |
|------|------|
| 用户名 | 3~20 字符, 允许字母、数字、下划线, 唯一 |
| 邮箱 | 标准邮箱格式, 唯一 |
| 密码 | 8~100 字符, 必须含字母和数字 |
| 论文标题 | 5~200 字符 |
| 论文摘要 | 20~2000 字符 |
| PDF 文件 | 仅 PDF 格式, ≤ 10MB |
| 评分 | 整数 1~5 |
| 评论内容 | 1~5000 字符 |
| 每论文每用户评分 | 唯一 (一个用户对一篇论文只能评一次) |
| 每用户每日上传论文 | ≤ 3 篇 |
